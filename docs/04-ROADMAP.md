# 04 — Roadmap

Status: **Directional after Build 001; sequence not frozen**

## Build 001 — Permanent spine

Prove persistent correspondence, sparse retained concepts, virtualization-safe identity, conservative cold recovery, provider isolation, bounded deltas, condition waits, brokered semantic/visual/physical actuation, and a many-operation Program Host.

Build 001 implementation is feature-complete for the frozen slice and all currently executable noninteractive validation is green. Measured interactive acceptance has not yet run.

## Candidate later areas

Later work is promoted only when concrete workloads justify it.

### Provider and framework breadth

- WinUI 3, WinForms, Qt, Java Accessibility, Chromium/Electron, and legacy MSAA coverage;
- framework-specific identity evidence where the framework documents it;
- optional UIA Remote Operations for measured cross-process call reduction;
- adaptive worker affinity if Build 001 measurements justify it.

### Deeper visual/custom UI

- richer visual feature extraction and OCR fallback;
- better representation of owner-drawn and inaccessible surfaces;
- Desktop Duplication for composed-monitor truth where WGC is unsuitable;
- drag/drop, touch, and pen only after the core target model is proven.

### Cross-substrate composition

- browser upload to Common Item Dialog to filesystem truth and back;
- IDE window to CODEeye workspace correlations;
- document-window to future DOCSeye document correlations;
- application-native semantic adapters for high-value domains.

### Session and deployment breadth

- multiple simultaneous interactive sessions;
- RDP/disconnected-session behavior;
- virtual desktops and virtualized/cloud desktops;
- elevated/UIAccess deployment only if an actual capability requires it;
- service/broker topology only when it buys proven coverage.

### Scale and hardening

- large retained worlds and higher event rates;
- provider-health heuristics and worker allocation policy;
- database compaction and longer-lived operating continuity;
- protocol evolution and provider-neutral seams;
- a second platform only to pressure-test which abstractions are genuinely portable.

## Explicitly not a roadmap promise

The roadmap does not commit DESKTOPeye to universal app plugins, continuous video, a full desktop mirror, a human automation designer, a graph database, DLL injection, a driver, an action ledger, or project-specific policy machinery.
